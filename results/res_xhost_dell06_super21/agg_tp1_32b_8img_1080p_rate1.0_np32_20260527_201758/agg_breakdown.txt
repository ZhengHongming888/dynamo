====================================================================================================
WHY DISAGG IS WORSE THAN AGG (key reasons)
====================================================================================================

1. PD GPU forward_duration:
   agg:       34895 ms
   disagg:     8627 ms  (0.25× higher)
   → disagg PD has more work per request because it must integrate NIXL-arrived
     embeddings, splitting visual prefill into multiple smaller batches.

2. Prefill batch fragmentation:
   agg prefill events:     full chunks=32, small batches (<200)=25
   disagg prefill events:  full chunks=31, small batches (<200)=26
   agg total prefill events: 57
   disagg total prefill events: 57

3. NIXL handoff overhead (disagg only):
   agg has NO NIXL events — encoder runs inline in same process as LLM
   disagg adds: Created Descriptor + Created ReadOp + NIXL wire + scheduler hop
   Per request: ~1-3 s under contention, even when wire itself is ~1 s

4. KV cache budget:
   agg: max_total_num_tokens=695,136 (mem-fraction=0.85)
   disagg: max_total_num_tokens=467,072 (mem-fraction=0.65, must reserve for NIXL buffers)
   → agg has 49% more KV → can batch decode of more requests simultaneously

5. Encoder ViT pipelining:
   agg: encoder (ViT) and decoder (LLM) pipeline within SGLang scheduler
   disagg: encoder is on a separate host → must wait for cross-host TCP+RDMA before PD prefill
